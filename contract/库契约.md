# 库契约 v1（冻结）

> 2026-10-29 起生效。本文件是「人格工坊」与一切聊天程序（QQ 通道器 / DSH / 任意智能体）之间的接口协议。
>
> 一句话：**工坊产出的库是通用资产**。任何聊天工具只要按本契约读库、写会话，就能让同一个"人"接进自己的对话，不需要理解工坊内部实现。
>
> schema 冻结原则：表结构不再改动（不加列、不改列、不删表）。通用性靠**约定**（命名空间、词表）扩展，不靠改 schema。

## 一、库目录结构（冻结）

```
<库名>/
├── agents.md           # 归纳AI作业规程
├── index.md            # 人格总括（每轮注入的总括段 + 路由段）
├── log.md              # 追加式时间线
├── preferences.toml    # 库侧配置（见第四节）
├── raw/                # 原始素材（用户写，永不改内容；归纳后加 .已归纳 后缀）
│   ├── identity.md     # 身份母本（人工可反复改写）
│   └── assets/         # 图片
├── wiki/               # 人格知识九页（工坊 ingest 维护）
│   ├── identity.md traits.md speech.md reactions.md values.md
│   ├── relationships.md memories.md boundaries.md exemplars.md
│   └── （禁止子目录——记忆层与 wiki/ 平级，不许塞进来）
├── memory/             # 记忆层（工坊 ingest 维护）
│   ├── _hub/           # 四张分类索引：people / projects / domains / timeline
│   ├── people/ projects/ domains/ timeline/
│   └── pending/        # 未批准条目，不进检索
└── data/               # 程序数据
    ├── sessions.db     # ★ 通用会话记录（聊天程序唯一写者，见第三节）
    └── identity_history/  # 身份母本历史备份
```

## 二、读写权限表（谁能动什么，一格都不许越）

| 路径 | 工坊 | 聊天程序 | 用户 |
|---|---|---|---|
| `index.md` `wiki/` `log.md` `memory/` | **写**（ingest/lint） | 只读 | 只读 |
| `raw/`（除 identity.md） | 读（ingest 收料） | 只读 | **写**（塞素材） |
| `raw/identity.md` | 写（控制台「身份」页） | 只读 | 写 |
| `preferences.toml` | **唯一写者** | 只读 | 经工坊控制台写 |
| `data/sessions.db` | 只读（试聊/蒸馏读取） | **唯一写者** | — |
| `data/identity_history/` | 写（控制台备份） | — | — |

原则重申：**聊天AI 绝不改写人格内容**。实战对话要回流，由聊天程序按 schema 写 sessions.db，或用户收集后塞进 raw 走 ingest。

## 三、sessions.db schema v1（冻结）

建库 SQL 与 `sessions_schema.sql` 一字不差。字段语义：

### messages
| 列 | 类型 | 语义 |
|---|---|---|
| id | INTEGER PK | 自增序号 |
| session_id | TEXT NOT NULL | 会话标识，格式见下方命名空间约定 |
| role | TEXT NOT NULL | `user` / `assistant`（必需）；`system` 允许；其他值原样存原样读 |
| content | TEXT NOT NULL | 消息正文（纯文本，不含"名字: "前缀） |
| ts | REAL NOT NULL | Unix 时间戳（秒，浮点） |
| msg_key | TEXT | 通道侧去重键，格式开放（重连重放用） |
| user_id | TEXT | 说这话的人的 ID（见下）；assistant 行为 NULL |

### sessions / summaries / seen / profiles
- `sessions(session_id, n, last_ts)`：会话索引，聊天程序维护。
- `summaries(session_id, summary, upto_id, updated)`：滚动摘要，聊天程序维护，工坊不解读。
- `seen(key, ts)`：通道侧去重表，纯通道私有，其他程序无视。
- `profiles(user_id, user_name, first_seen, last_seen, turns)`：说话人档案，按 user_id 聚合。

### 通用会话约定（通用性的全部来源，不改 schema）

1. **session_id 命名空间**：格式 `<命名空间>:<范围ID>`，冒号前是通道注册的名字。
   - 已注册：`private`（旧，私聊）、`group`（旧，群聊）——**永久保留兼容**；
   - 开放注册：新工具取自己的前缀即可，如 `qq-group:123456`、`qq-private:u_abc`、`dsh:会话ID`、`workbuddy:会话ID`。前缀不冲突即互不干扰，不同命名空间天然隔离。
2. **user_id 开放**：QQ openid、真实 QQ 号、DSH 用户 ID、智能体侧用户标识……都是合法字符串，跨通道不要求统一。
3. **会话隔离**：同一 session_id 内消息共享上下文；上下文怎么拼（近 N 轮 + 摘要）是聊天程序自己的事，工坊不管。
4. **建库规则**：聊天程序首次连接时若 `data/sessions.db` 不存在，按 `sessions_schema.sql` 建库；**已存在则禁止任何 DDL**（schema 冻结）。
5. **并发**：多程序同时连同一个 sessions.db 不受契约支持（一库一连接，沿用现有拦截逻辑）；跨程序采集走工坊的只读入口。

## 四、preferences.toml 归属

库侧段落（**工坊唯一写者**，聊天程序只读复用）：
`[persona]` `[bot]` `[owner]` `[llm]` `[memory]` `[sim]` `[distill]`

通道侧段落（**通道器唯一写者**，目标状态是迁出库文件）：
`[adapter]` `[trigger]` `[batch]` `[gate]` `[rate_limit]` `[reply]` `[drift]`

过渡期（拆分完成前）允许通道段落暂留库内 preferences.toml，工坊写入时不得触碰这些段落；迁移完成后库内文件只保留库侧段落。

## 五、契约校验

工坊 lint 增加确定性检查（`bridge/lint.py`，一条模型都不调）：

| code | 级别 | 内容 |
|---|---|---|
| contract-missing | error/warn | raw/ 缺失；agents.md / log.md / preferences.toml / memory/_hub 缺失 |
| contract-layout | warn | wiki/ 出现子目录 |
| contract-schema | error | sessions.db 缺表 / messages 缺列 |
| contract-schema | warn | messages 出现契约外的列 |
