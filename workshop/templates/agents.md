# agents.md — 归纳AI作业规程

> 本文件是给**归纳AI（agents）**看的作业规范。聊天AI 不读本文件、也不改写库中的任何文件。归纳AI 是库里唯一的写者。
>
> 主界面顶栏的「归纳 raw」按钮由程序代跑这套规程（`bridge/ingest.py` + `bridge/ingest_rules.py`）：
> 它读 `raw/` 的新素材、按本文改 `wiki/` `index.md` `log.md`，收完把素材改名加 `.已归纳`。
> 程序只是这个角色的执行手，聊天AI 仍然一个字节都不许写。

## 一、角色与权限

| 角色 | 读 | 写 | 职责 |
|---|---|---|---|
| 归纳AI（agents） | raw / wiki / index / log | wiki / index / log（仅追加） | 提炼、编入、重写总括、体检 |
| 聊天AI | index（每轮）+ wiki（按需） | 无 | 理解语境，按人设回答 |
| 用户（你） | 全部 | 仅 raw（含 raw/identity.md） | 塞素材、审核、定重点 |
| 程序（控制台 / 聊天端） | 全部 | raw/identity.md、raw 素材改名（不动内容）、preferences.toml、data/ | 落身份母本、存本库的整份配置、存会话与备份 |

原则：**聊天AI 绝不改写人格内容**（wiki / index / raw 一个字节都不动），它只往 `data/sessions.db` 写会话记录；实战对话要回流时，由用户收集后放进 raw，再走 ingest。

身份母本 `raw/identity.md` 也走这一分工：人工写（控制台「身份」页），归纳AI 读了提炼进 `wiki/identity.md`。详见第七节。


## 三、人格库特有的六条核心原则

（这是与普通事实知识库的关键差异，务必遵守）

1. **从"事实"到"行为"**：wiki 存的是"这个人怎么说话、怎么反应"，不是客观事实。写特质、写反应模式、写语言习惯，不写百科条目。
2. **抽象结论必须挂证据摘录**：每条"毒舌 / 温柔 / 冷静"之类标签，都要附 raw 里的原句摘录，并标 source。风格靠摘录传递，不靠形容词。
3. **矛盾要"情境化"，不要"消解"**：人本就矛盾（平时温和、碰到底线爆炸）。写成"在 X 情境 → Y 表现"的条件规则，保留矛盾作为立体度，不合并成唯一结论。
4. **范例语料是最高优先级素材**：凡 raw 里"最像本人"的原话 / 对话，优先编入 exemplars.md 作 few-shot 标准样本。
5. **index 必须"有界 + 独立可用 + 可迁移"**：总括段要短到每轮能注入、不查 wiki 也能基本成立，且写"原则 + 倾向"而非固定话术。
6. **实战对话回流 raw**：聊天AI 实战中表现好 / 坏的对话，由用户收集后塞回 raw，再走 ingest 继续提炼。

## 四、工作流

### A. ingest（收料归纳）

收到一条新 raw 后：

1. 通读 raw，识别可提炼的人格信息（身份、特质、语言、反应、价值、关系、记忆、边界、范例）。
   素材带成品头（`用途 / 分类 / 情境 / 构成` 那几行）时，**先按第六节读头**再读正文：
   头决定"往哪页、算不算硬证据"，正文决定"怎么写"。
2. 更新对应 wiki 页：新增或修订条目，**每条抽象结论附证据摘录 + source**。
3. 判断置信度（high = 多处证据一致 / medium = 单处但有代表性 / low = 推断或孤立）。低置信度要标注，不写成硬人设。
4. 与既有条目冲突时：不删旧条目，改写为"情境化"条件规则，或在旧条目下补充说明。
5. 重写 index.md 的总括段（若人设画像有实质变化）与路由段。
6. 在 log.md 末尾追加一条：`## [YYYY-MM-DD] ingest | <素材名>`。

### B. index 重建

- 总括段：一句话人设 + 3~7 条核心特质 + 2~4 条语言风格要点 + 1~2 条底线。
- 路由段：维护"情境 → wiki 页"映射表。
- 铁律：写"原则 + 倾向"，不写"固定话术"。例：写"打招呼随意带点痞气、按亲疏切换"，不写"必须回'哟'"。

### C. lint（体检）

定期检查：

- 页间矛盾未情境化
- 抽象标签缺证据摘录
- 低置信度条目被误当硬人设
- index 总括与 wiki 不一致
- 孤立页面（无任何链接 / 引用）
- 缺失的关键维度（如只有语言风格、没有价值观）

## 五、frontmatter 约定

每个 wiki 页头部统一五字段：

```yaml
---
type: identity | trait | speech | reaction | value | relation | memory | boundary | exemplar
tags: [..]
source: ""      # 指向 raw 素材路径或文件名
confidence: low # high / medium / low
updated: YYYY-MM-DD
---
```

## 六、raw 规范

- 文本素材：`raw/YYYY-MM-DD_描述.md`，一个文件一段经历 / 一篇素材。
- 图片素材：放 `raw/assets/`，文件名保留描述（如 `raw/assets/YYYY-MM-DD_某场景.png`）。
- raw 一旦放入即视为只读，归纳AI 只读不改。
- 图片处理：归纳AI 先读文本，再单独查看相关图片补充上下文（LLM 无法一次读含内联图片的 md）。

### 成品头（素材台收的稿怎么读）

raw 里的文本素材有三个来源：实战对话回流、蒸馏器从小说里摘的对话段、素材台收的反应卡。
只有蒸馏稿带下面这套固定头部，字段全是给归纳AI 的作业提示，逐行含义如下：
（素材台 2026-10-27 起只出**反应样式稿**，它没有下面这些字段，按第九节读，不要按本节反推。）

| 字段 | 含义 | 怎么用 |
|---|---|---|
| `用途：` | 这段主要能补哪几页 | 作业方向，**不是结论**。内容撑不起那一页就别硬编 |
| `分类：` | 情境类别（日常搭话 / 情绪反应 / 冲突对峙 / 价值判断 / 回忆往事 / 关系试探 / 边界触碰 / 自我介绍 之一） | `用途` 由它推导；两行打架时**以分类为准**。2026-10-24 之前导出的旧稿没有这一行，按 `用途` 首项反推，别当缺字段报错 |
| `情境：` | `关系档｜场合` | **首段是关系档，且是档位的唯一来源**。只认这一段，不要从内容反推。**首段是 `—` 表示还没归过档**（蒸馏稿的常态）：这段先不往 relationships.md 编，等人工在素材台划完档再收，不要自己替它贴一档 |
| `张力：` | 当时的卡点（她为什么不好接） | 判断"情境化条件"用；可作 traits / reactions 的条件前半句 |
| `对方：` | 对方是谁（想拿到什么） | 归 relationships 的对象；群聊/私聊属场合，不是第四档 |
| `构成：` | 原文 N 句 / 人工原话 N 句 / AI 采纳 N 句 / 未采纳 N 条 | **置信度的唯一依据**，见下。`原文` 只出现在蒸馏稿里 |
| `来源：` | `小说《书名》第十二章（第 340~352 段）` | 蒸馏稿的溯源，不是结论。觉得哪句可疑按段号回原文对 |
| `批注：` | 人工标注"哪句最像" | 有批注就按批注挑 exemplars，不要自己另选 |

口径五条，别弄错：

1. **AI 采纳 ≠ 她原话。** 只有 `人工原话` 才算 high 证据；AI 采纳的是"模型对人设的理解 + 人工裁决"，
   最高给 medium。全篇都是 AI 采纳时，只能当补充语料，不能写成硬人设。
2. **小说原文算中间置信度。** 蒸馏器直取的小说台词（`原文 N 句`）是作者写出来的设定级证据：
   能立住"她会这么说"，最高 medium，**不能当 high，也不能顶替本人聊天原话**。
   `用途` 含 exemplars 时，小说原句只作风格参照；要当 few-shot，优先用 `人工原话`。
3. **`批注` 里的「推定 N 句」是降级信号。** 那是程序按人称代词 / 整段唯一人名 / 轮次交替推出来的说话人，
   成段时就已经可能错。这一段里推定句占比过高时按 low 收，或只取用户明确批注过的那几句。
4. **记最终条件，不记最初抽到的卡。** 条件（关系 / 场合 / 卡点 / 对方）在成稿前可改，
   成品头写的是收稿那一刻的版本。与对话内容明显不符时才按内容改档，并在此条标 `conflict: <文件名>`。
5. **一张卡只有一个关系档。** 句子的说话人可以中途换、顺序可以调，但档位属于这张卡，不属于某一句话。
   蒸馏稿同理：`情境` 首段是提取时选的档，同一段里不会出现两档。

## 七、母本例外（raw/identity.md）

身份不是"从素材里归纳出来的"，是"先立住、再拿素材去验证"的。所以 `raw/identity.md` 单独对待：

| 项 | 规则 |
|---|---|
| 文件名 | 固定 `raw/identity.md`，不受 `raw/YYYY-MM-DD_描述.md` 命名规范约束 |
| 写权 | **只有人工**（控制台「身份」页保存）。归纳AI 只读 |
| 改权 | 允许反复改写（这是 raw 唯一的例外）；旧版自动备份到 `data/identity_history/` |
| 与其他 raw | 其余 raw 仍为只读、只增不改 |

归纳AI 的处理方式：

1. **可改**：重排结构、润色措辞、合并重复、把散句整理成条目、补写原文显然隐含但没写明的推论（后者标 `confidence: medium`）。
2. **不可改**：删减事实点、替换设定、把"她不会做的事"改写成"她会"、凭空补一段母本里没有的经历。
3. 母本与既有 wiki 条目冲突 → 以母本为准改写 wiki，并在该条下标 `conflict: raw/identity.md`，交人工裁决；不得静默覆盖。
4. `wiki/identity.md` 的 `source` 恒为 `raw/identity.md`，`confidence` 为 `high`。
5. `wiki/values.md` 以母本「价值观与立场」一节为**唯一权威源**：只搬运、只细化，不从对话素材里给她立新立场。
   对话里出现相反说法 → 用 `conflict` 记一条并写清出处，不覆盖；母本这一节空着时 values.md 宁可留空，
   也不许用"看起来像她"的立场填满。
6. 母本没写的维度（如 `speech.md` 的语气细节），才从其它 raw 素材归纳。

流程上的位置：

```
人工写 raw/identity.md  →  归纳AI ingest  →  wiki/identity.md
                                              ↓
                                        重写 index 总括段
```

母本只落在 raw，不直接改 wiki、不直接改 index。index 空着不影响母本保存；
总括段由归纳AI 从 wiki 长出来，人工不碰。

母本骨架固定八节：一句话是谁 / 生活半径 / 关系三档 / 说话习惯（QQ 文字）/ 底线雷区 / 价值观与立场 / 想要与怕 / 不存在的东西。
骨架同时定义在工具侧 `workshop/seed.py` 的 `SECTIONS` 与 `TEMPLATE`，改骨架必须两边一起改，
否则控制台新建的母本与库里这份会对不上。关系只三档，不写具体人名清单。

## 八、关系语域（relationships.md 三档）

"对谁说话方式不同、人格基调不变"这件事，全部落在 `relationships.md` 的三节里：
`## 与拥有者` / `## 对熟人` / `## 对陌生人`。

**只允许改六个旋钮**：称呼、直接度、话量、解释不解释、会不会主动追问、允许露出的情绪。

**不许动的东西（动了就是基调漂移，不是语域变化）**：

| 不许动 | 该在哪页 |
|---|---|
| 价值判断、立场 | values.md |
| 幽默方式、口癖、语气词 | speech.md |
| 句法节奏、标点习惯 | speech.md |
| 性格底色、内在矛盾 | traits.md |
| 底线雷区 | boundaries.md |

三档之间的差别只该是**距离**，不是**换个人**。写的时候用这条自检：
把三档遮住称呼再看，如果读起来像三个不同性格的人，就是写错了——三档应该一眼能认出是同一个人。

写法要求：

- 三节结构一致，同一档内按六个旋钮逐条写，不要写成段落。
- 每档至少一句例句（`> "..."`），例句来自 raw 或母本；没有例句就先留空，不要编。
- 每档挂 `source` / `confidence`：母本原文 → high；AI 从零推断 → low，标注待核。
- 三节互不引用。不要在"对陌生人"里写"比对主人冷淡"——比照式写法会让模型同时想到两档。

工具侧对应的机制：按当前对方属于哪一档，**只抽那一节**注入提示词（不整页注入）。
所以三档同时写满是安全的，不会互相打架；某一节空着就是那一档不特殊对待，走内置分寸。

与母本的边界：`raw/identity.md` 的「关系三档」只写"这一档算什么、默认多远"这类事实；
称呼、直接度、话量这些**说法**仍只写在本页，不回写到母本，也不在本页重述"她是谁"。

平台边界：本库面向 QQ 文字聊天。群聊 / 私聊属于场合，不是关系档——
场合差异（群里搭不搭话、被 @ 才回）写在 `speech.md`，不在本页再开第四档。

素材台造料时也能指定档位：成品头的 `情境` 首段就是档位（`陌生人｜深夜的微信`），导入 raw 后按这一段归到对应节。
这四行覆盖统计（关系 / 关系·拥有者 / 关系·熟人 / 关系·陌生人）是判断"三档是否真有料"的唯一依据——
只收了一段关系素材就让三档都"有内容"，那是归纳AI 在替素材编。

## 九、反应样式稿（蒸馏器的第二种产物）

两种产物都叫反应样式稿：**不导出对白，只导出"面对这类刺激怎么回"**。蒸馏器从原文摘，素材台从母本推，两条产线共用一套内核和同一份成品头。文件名形如
`raw/YYYY-MM-DD_反应_描述.md`，头部第一行是 `形态：反应样式`。

看到这行，就按本节读，**不要再套第六节的对话稿规则**——它没有对白、没有身份、没有关系，
`情境 / 张力 / 对方 / 构成` 这几个字段不存在也不算缺，不要反推、不要补全。

| 字段 | 意思 | 怎么用 |
|---|---|---|
| `形态：` | 固定 `反应样式` | 分流依据 |
| `档位：` | `拥有者` / `熟人` / `陌生人` / `—` | **只有人工判断，模型不给**。`—` 表示不分档。分档时写成「被索取｜熟人 → …」，它是条件不是关系 |
| `刺激：` | 十二类之一（被逼近 / 被轻视 / 被关心 / 被示好 / 被道歉 / 被逗 / 被依赖 / 被误解 / 被索取 / 被试探 / 被指责 / 被冷落） | `reactions.md` 的条件前半句 |
| `场景：` | 一句话说清被什么逼到 | 条件后半句。**不是关系、不是事实** |
| `情绪：` | `起点 → 终点` | 并入同一条条件 |
| `回应：` | 可检验的动作序列（先反问 / 再给结论） | `reactions.md` 的行为条目 |
| `话量 / 句长 / 追问` | 节奏 | `speech.md` 的句法节奏 |
| `露出：` | 允许露出的情绪 | `reactions.md` 该条件下，**不动 traits** |
| `语言：` | 口癖、标点、语气词 | `speech.md` |
| `不做：` | 这类刺激下不会做的事 | `reactions.md` 该条件的「不做」列 |
| `置信：` | 固定 medium | 上限，不许升 high |
| `审：` | `已过` / `未过` | **未过的整份不收**，直接跳过 |

**固定映射，不许自由归页**：

| 进哪页 | 内容 |
|---|---|
| `reactions.md` | 档位 + 刺激 + 场景 + 情绪 + 回应 + 露出 + 不做 |
| `speech.md` | 句长 + 语言 |
| `relationships.md` | **仅当 `档位` 不是 `—` 时**：档位对应的那一节，填六个旋钮——称呼 / 直接度 / 话量 / 解释不解释 / 主动追问 / 情绪露出 |
| `exemplars.md` | **仅当有 `范例：已核` 时**，且只准写进 `## 行为范例` 小节（条件 → 回应，不是原句） |

**档位与素材卡的 `情境` 首段同权**：档位写的是什么，就归到哪一节，不猜、不改写、不并档。

| `档位：` | 归到 `relationships.md` 的 |
|---|---|
| `拥有者` | `## 与拥有者` |
| `熟人` | `## 对熟人` |
| `陌生人` | `## 对陌生人` |
| `—` | 不归关系页 |

和对话稿成品里的 `情境：<档位>｜…` 走同一条路、同一份置信度规则。

关系页的六个旋钮本来就都是**规则**，不是具体人——「不喊称呼，直接说事」「一个字回绝」
这类写法本来就不指对象。所以反应卡六项都能补，包括称呼。

只有三样东西它给不了，遇到就留空，不要替它编：

| 给不了的 | 为什么 | 谁能给 |
|---|---|---|
| 具体称呼词（"老周"） | 卡上没有人名 | `raw/identity.md` 的「关系三档」+ `owner.call_me` |
| 例句 | 反应卡按设计不带原句 | 对话稿成品、真人原话 |
| 对象（"对方是谁"） | 它只知道档位，不知道人 | 对话稿成品的 `对方：` 那一行 |

也就是说：反应卡能写「称呼：不喊，直接说事」，不能写「称呼：喊他老周」。
后者由上面的校验兜住——`父亲`、`大人` 都在关系称呼黑名单里，模型写不出来。

`档位：—` 的卡不分档，只进 reactions / speech，不碰关系页。

页内已有真人写的条目时，反应卡只作**补充与印证**，冲突以人工条目为准。

### 刺激覆盖表（`刺激：` 怎么落类）

每个类各管一段，一句话说清边界。**落不进这些类的就不是反应卡素材**，不要硬塞。
（与 `react_style.COVERAGE` 同源；改这里要同时改那张表。）

| 类 | 边界 | 常见说法 |
|---|---|---|
| 被逼近 | 对方在推你：逼表态、逼选边、连问不放、当面堵住 | 被逼表态 / 被催 / 被突然点名 |
| 被轻视 | 你的分量被贬低：看不起、嘲讽、好意被客套挡回、答应的事不做 | 被贬低 / 示好被挡回 / 对方食言 |
| 被关心 | 对方的动作落在你身上：问你状态、替你分担、让你歇着 | 被关心 / 被安慰 |
| 被示好 | 对方主动给正向的东西：表白、夸奖、感谢、当面承诺、分享好消息 | 被表白 / 被夸 / 被感谢 |
| 被道歉 | 对方认错、示弱、递台阶 | 被道歉 / 对方说对不起 |
| 被逗 | 对方在玩，没有目的：开玩笑、调侃、逗她、撩她 | 被调侃 / 被开玩笑 / 被逗笑 |
| 被依赖 | 对方把软的一面交过来：示弱、求助、要安慰、撒娇 | 被示弱 / 被求助 / 被撒娇 |
| 被误解 | 对方按错的理解看你：曲解、冤枉、认成另一个人 | 被曲解 / 被冤枉 |
| 被索取 | 对方要你的东西：要时间、要判断、要劳动、要情绪 | 被求评价 / 被交办 / 被支使 |
| 被试探 | 对方绕着来：套话、旁敲侧击、抓你的把柄 | 被试探 / 被绕弯评价 / 被抓包 |
| 被指责 | 对方的矛头指向你：责问、追责、说教、翻旧账、推锅 | 被翻旧账 / 被指出做错 / 被推锅 |
| 被冷落 | 对方不给回应：冷场、没人理、消息不回 | 冷场 / 被晾着 |

「被逗」和「被试探」容易混，看对方有没有目的：逗是玩，试探是想从你这儿套出点什么。
「被依赖」和「被关心」也容易混，看软的一面在谁身上：对方在照顾你 = 被关心；对方把软处交给你 = 被依赖。

**三样不进反应卡**：

| 不进 | 为什么 | 该去哪 |
|---|---|---|
| 她主动安慰人 / 主动催人 / 主动开话题 | 她发起的行为没有被刺激，反应卡记的是"被什么逼到怎么回" | `exemplars.md` 的 `## 行为范例`，或对话稿 |
| 单纯的情绪状态（开心 / 兴奋 / 难过） | 反应卡记的是"被什么逼到、怎么回"，不是情绪本身 | `traits.md` / `speech.md` |
| 与人的客观事实（几岁、认识谁） | 不是刺激 | `identity.md` |

注意「被依赖」和"她主动安慰人"是两回事：对方示弱求助 → 进 `被依赖`（她怎么接这一手）；
她自己看对方状态不好就去哄 → 不进反应卡。

落类时**先看对方做了什么，再看她怎么回**：同一句"你怎么又不回我"，
追问消息时是 `被逼近`，翻旧账时是 `被指责`——类由对方那一手决定，不由她的反应决定。

### 范例开关（`范例：已核`）

反应卡默认不进 exemplars。只有人勾了「可作范例」，成品头才会多一行 `范例：已核`，
想给 few-shot 就再补一行 `例句：`（人挑的一句原话，≤40 字，没有就别硬编）。

| 项 | 规则 |
|---|---|
| 写进哪 | `exemplars.md` 的 `## 行为范例`，**不是** `## 原话摘录` |
| 写成什么 | 「条件 → 回应 → 语言」，一条目一件事，不要抄成句子 |
| 置信 | 恒 `medium`；带 `例句：` 的可标 medium+，**永不升 high** |
| 没勾范例 | 用途里不会出现 exemplars.md，出现了就是程序出错，报 lint |
| 没过审的卡 | 程序根本不让勾范例，导不出来；见到了就是漏审，报 lint |

`## 行为范例` 是**补位，不是替代**：它的 few-shot 效果弱于真人原话。
所以 `## 原话摘录` 仍是第一优先级，别因为有了这一节就不收对话稿了。

三条禁令：

1. 不得把反应卡写进 identity / boundaries，也不得写进 exemplars 的 `## 原话摘录`；
   `范例：已核` 的卡只准进 `## 行为范例`（那是条件 → 回应，不是原句）。
   relationships 只接受上面那张表里
   允许的六个旋钮，**不许**借它写对象、具体称呼词或"她跟谁什么关系"。
2. 不得引入专名、称谓、职业、地名、事件。`场景` 是抽象条件，不是发生过的事——
   写"被连续追问"，不写"被父亲在书房追问"。档位只能写三个固定词，不能写成"她师父"。
3. 与 wiki 既有条目或真人原话冲突时，**以 wiki / 原话为准**，反应卡退让，并在 log 记一条 `conflict`。

lint 增查五条：① identity / boundaries 里出现 `source` 指向反应卡文件 → 报错；
② exemplars 的 `## 原话摘录` 里出现 source 指向反应卡 → 报错；
③ wiki 里出现专名 / 具体称谓词 / 具体事件而 source 是反应卡 → 报错
（"不喊称呼"是规则，"老周"是称谓，后者才算）；
④ 同一刺激条件在 reactions.md 重复出现且写法互斥 → 提示合并；
⑤ `## 行为范例` 里引用了反应卡却没标 `范例：已核` → 报错。

## 十、写法红线

- 写"原则 + 倾向"，不写死模板、不写逐字话术（exemplars.md 的摘录除外，那里就是要原句）。
- 抽象标签必须挂证据，否则不写。
- 永不删除、永不修改 raw 与 log 的历史条目。
- 只追加 log，不重写历史。
- 知识（若人设带专业知识）进 wiki 按需加载，不塞进 index 总括段。

## 十一、记忆层写入（memory/）

记忆层与人格层物理分家：`wiki/` 是"她是谁"，`memory/` 是"她记得什么"。
两棵树不许混：`wiki/` 下不加子目录，记忆页一律放 `memory/`。

### 写入决策树

抽出一条事实后按顺序判断，前一条命中就停：

1. **已在某页「## 事实」段有同义表述** → 不动正文；来源不同则追加 `source`，刷新 `updated`。
2. **与某页现有说法矛盾** → 不覆盖。两说并存，`status: conflict`，加「## 冲突」段写明各自来源，交人工裁。
3. **属已有页的新侧面** → 追加到对应小节；单页超 4000 字则拆页，母页留一行 `[[子页]]` 摘要。
4. **属新实体且满足三现/专名原则** → 新建页，挂到对应 hub，并回链母页。
5. **都不满足** → 写进 `timeline/YYYY-MM.md` 一条 bullet，不建页。

### 硬规则

1. 只增事实、不改历史：人工写的原话段落一律不动。
2. 无出处不落盘：任何「事实」行必须带 `source`；无 source 的只进「## 待查」。
3. 句式禁令：事实行不得出现性格断言（她总是 / 一向 / 从来 / 本质 / 其实很 / 这人 / 天生 / 根本）。只写"何时、谁、做了什么"，命中即拒收。
4. 日期只进 `timeline/YYYY-MM.md`：不建日期目录、不建日期页。
5. 每次写入追加 `log.md` 一条，前缀 `merge / newpage / relink / doctor / shift`。
6. 低置信不进检索：来源标为"场景设定"的 `confidence: low` 条目只作情境借用，不当人生事实。

### 写权边界

| 目标 | 权限 |
|---|---|
| `memory/**` | 可写 |
| `wiki/identity.md`、`traits.md`、`speech.md`、`values.md`、`boundaries.md` | **只读**。需变更时写 `memory/pending/persona-proposal.md`，交人工裁决 |
| `wiki/relationships.md` | 只允许改档位归属，不改六个旋钮的写法 |
| `raw/**`、`log.md` 历史条目 | 只读 |

### 不注入的内容

- `memory/pending/**` 与 frontmatter 标 `scope: system` 的页不进检索。
- `scope: system` 用于存档实现细节：被注入会让角色说出"我的记忆库走 wiki 模式"这类 OOC 内容。

### 一句话判据

打开任意 `memory/people/<某人>.md`，里面只应出现"什么时候、谁、做了什么"。
若出现"她是个怎样的人"，那句该在 `traits.md` 里，且必须是人写进去的，不是归纳出来的。
